# Read API Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Expose `indexdb.read.Reader` over HTTP via a thin FastAPI service so the algorithm team can query Mongo/Milvus/Elasticsearch with plain HTTP requests — no `pymongo`/`pymilvus`/`elasticsearch` client libs, no DB credentials.

**Architecture:** `layer_5/api/main.py` is a thin consumer of `indexdb.read.Reader` — one REST endpoint per `Reader` method, a lazily-constructed module-level `Reader` singleton, and a static-API-key auth dependency. It runs as a new `api` service in the existing `docker-compose.yaml` stack, built from the same image as `app`, with its port published to the host like the DB ports already are.

**Tech Stack:** FastAPI + Uvicorn, added to the existing `requirements.txt` / `Dockerfile` / `docker-compose.yaml`.

**Full design:** `docs/superpowers/specs/2026-07-29-read-api-design.md`

## Global Constraints

- `api/main.py` is a consumer of `indexdb.read.Reader`, not part of `indexdb/` — no read/write DB logic lives in `api/`.
- The `Reader` instance is constructed once (lazily, on first request, cached in a module-level global) — not per-request.
- No vector/text encoding happens in this service. `search_vector` accepts a raw `float[]` in the request body.
- `Hit` shape from `Reader.search_vector`/`search_text` is passed through unchanged: `{keyframe_id, video_id, shot_id, timestamp_ms, score}`.
- Auth: single static API key from env var `API_KEY`, required via header `X-API-Key` on every endpoint except `/health`. Missing/wrong key → `401`.
- Docker build context stays `.` (`layer_5/`) — the Dockerfile itself is not modified.
- Host port for the new service: `8020` (`8000`, `8010`, `8082` are already taken on this shared host — see `docker-compose.override.yaml`).
- Test convention: `@pytest.mark.integration` for any test touching real Mongo/ES/Milvus (per `pytest.ini`); tests that only exercise the FastAPI app in isolation (e.g. `/health`, auth rejection) need no marker.

```python
import os
from fastapi import Depends, FastAPI, Header, HTTPException
from pydantic import BaseModel
from indexdb.read import Reader

app = FastAPI()

_reader: Reader | None = None


def get_reader() -> Reader:
    global _reader
    if _reader is None:
        _reader = Reader()
    return _reader


def require_api_key(x_api_key: str = Header(default="")) -> None:
    expected = os.getenv("API_KEY", "")
    if not expected or x_api_key != expected:
        raise HTTPException(status_code=401, detail="invalid or missing API key")


class SearchVectorRequest(BaseModel):
    model: str
    vector: list[float]
    top_k: int = 100
    video_ids: list[str] | None = None


class SearchTextRequest(BaseModel):
    query: str
    top_k: int = 100
    video_ids: list[str] | None = None
    fields: list[str] | None = None


@app.get("/health")
def health():
    return {"status": "ok"}


@app.post("/search/vector", dependencies=[Depends(require_api_key)])
def search_vector(req: SearchVectorRequest, reader: Reader = Depends(get_reader)):
    return reader.search_vector(req.model, req.vector, req.top_k, req.video_ids)


@app.post("/search/text", dependencies=[Depends(require_api_key)])
def search_text(req: SearchTextRequest, reader: Reader = Depends(get_reader)):
    return reader.search_text(req.query, req.top_k, req.video_ids, req.fields)
```
